# 详细说明

## 数据结构

本章说明我们需要面对的数据。所有的数据都需要以 json 格式分层次存储在 ./database 中，并且可以被后台操作。以下所有加粗的对向，在代码中你需要以体育比赛中的专业名词命名。

首先你可以给数据库写必要的元数据，比如说所有的**赛事**的名字。

我们首先需要处理的数据是赛事。一个赛事有以下元数据：

- 文件名，英文。
- （中文）名称；
- 比赛日期（一个日期区间）。
- 比赛地点（一个中文地名）。
- **项目**列表。

一个赛事在数据库中的存在形式应当是一个名为该文件名的文件夹。下面首先有一个 json 存储上述元数据，然后是若干个子文件夹，表示其附属的项目。这里的项目是指男单、女单、男双、女双、男团、女团等这种项目。一个项目有以下元数据：

- 文件名，该文件名应该是赛事文件名-根据属性组合出的后缀。比如男子单打就可以写 赛事文件名-men-single 之类的。
- 属性，可以在（男子 / 女子 / 混合）*（单打 / 双打 / 团体）里面选。这将给出这个项目的中文名称。
- 赛程，可以从以下三种里面选：小组赛-淘汰赛，淘汰赛，循环赛。这将决定该项目的阶段列表，阶段列表的每个元素是一个**阶段**。

一个项目在数据库中的形式也是一个文件夹，下面有一个 json 存储上述元数据，然后是若干个子文件夹，表示其中附属的阶段。一个阶段总的来说包含以下元数据：

- 类型，可以是**小组赛** / **淘汰赛** / **循环赛**。
- **选手**列表，其中每一个选手还多一个值，叫做**种子级别**，这是一个正整数。

这个元数据应当储存在该阶段的目录下。根据类型的不同，每个阶段里面包含的数据也不同。该阶段的特有数据被存在另一个 json 文件中。

如果该阶段是一个小组赛，那么该阶段须包括：

- 是否抽签。
- **小组**列表。

每一个小组的数据包括：

- 小组人数。
- 出线人数。
- 选手列表。里面包括本组所有选手。
- **场次**列表。场次按照所有选手单循环产生。

如果该阶段是一个淘汰赛，那么该阶段须包括：

- 淘汰赛轮数。
- 场次列表。场次应该是一个深度为淘汰赛轮数的完全二叉树的所有边，其中信息可以从下往上递推。
- 是否抽签。
- 选手列表，这个是一个有序列表，给出每个位置上的选手。

如果该阶段是一个循环赛，那么该阶段须包括：

- 人数。
- 场次列表，应该按照所有选手单循环产生。

一个选手的数据包括：

- 性质。可以是选手，组合或者团体，或者“未决定”。
- 成员列表。可以是选手名字，双打组合里面两个人的名字的列表，和团体所有成员的列表。
- 队伍。

一个场次的数据包括：

- 选手 A，选手 B。
- 是否结束。
- **局**列表。

一个局是一个二元组，表示选手 A 对选手 B 的比分。以上是全部关于数据结构的说明。

## 前端

这是一个封闭于 ./webpage 之内的静态网页。要求是我需要能够把 ./webpage 里面的东西直接上传到 github，然后便可以在 github 上看到完整的信息。当然，database 的副本会被放在 ./wenpage 里面，你可以利用其中的数据，然后用脚本生成网页。

该网页所有页面必须要同时兼容移动端和桌面端。所有东西必须简洁、现代。

该网站首页是一个赛事列表。所有赛事必须按照时间从新到旧排序，展示中文名称、比赛日期和比赛地点。并且有一个超链接链接到该比赛的页面。每个赛事的样式都是一个卡片，该卡片的标题就是比赛名称，日期和地点都是副标题，超链接按钮是一个卡片右下角的箭头。

对于每一个比赛页面，显示该比赛的标题。下方展示一个项目列表。同样，每个项目都是一个卡片，标题是该项目的名称，副标题是赛程。有一个超链接连接到该项目的页面。

对于每一个项目页面，显示该项目所在比赛的标题（该项目的名称）。标题下面的副标题应当是该项目的赛程。如果是小组赛 - 淘汰赛，你需要让这个可以点，以切换小组赛 / 淘汰赛阶段的页面，具体地：

1. 如果小组赛没打完，那么不能点。
2. 如果小组赛打完了，那么默认从淘汰赛页面开始，点小组赛可以切换到小组赛页面，点淘汰赛页面可以换回来。

。再下面的内容根据阶段生成。

如果该阶段是一个循环赛，你暂时可以假设人数不多，不妨设就有 $n$ 个人。这时候你需要展示一张卡片，该卡片中包括以下两个部分：

1. 选手列表。给每个选手编号 $1, 2, ..., n$，显示一个列表。
2. 对阵图。这应当是一个 $(n + 1)\times (n + 2)$ 的表格，左上角的格子是空的，第一列从第二行开始往下写编号，第一行从第二列开始往右写编号，最后一列表头写排名。中间的格子里面，第 $i$ 行第 $j$ 列展示第 $i$ 位选手对第 $j$ 位选手的大比分。

选手列表本质上是一个 $n$ 行 $2$ 列的表格，左边一列写数字，右边一列展示选手，点一下右边那一列的单元格的会展开一个（可以点击外面任意位置或者某个按钮关闭的卡片，然后其他部分变暗）显示该选手的详细信息，具体呈现方法如下：

- 若该选手是一个单打选手，显示该选手的名字。详细信息卡片中标题写该选手名字，下面正常字体写该选手队伍。
- 若该选手是一个双打组合，显示该组合中两个成员，中间用 / 隔开，详细信息卡片中正常字体写该选手队伍。
- 若该选手是一个团体，显示该队伍名字。详细信息卡片中标题写队伍，正常字体写里面的成员列表，逗号隔开。
- 未决定的选手不能点。

对于对阵图，点一下 $i < j$ 的单元格会展开这一局的详细信息，弹出一个可以点击外面任意位置或者某个按钮关闭的卡片，然后其余部分变暗。展示比赛双方选手（按照展示选手的方法展示）、当前大比分、桌号、时间、本场次是否结束（已结束 / 未结束），然后下面是一个列表写每一局的比分。

如果本循环所有场次全部打完，用*循环赛排名计算逻辑*计算排名并显示。其他时候排名那一列直接空着。

在宽度足够的屏幕上，这两个表应该左右排列，对应行要对齐；在宽度不够的屏幕上，按照上下结构展示，此时不需要考虑对齐。你可以假设即便是手机也能容纳表格。

对于小组赛，每一个小组本质上是一个循环赛，因此用上面的信息展示。每一个卡片上额外展示以下信息：小组编号和出线人数（小组 #n（出线 x 人））。如果本小组所有场次全部打完，并且计算出了排名，将出线的选手在选手列表那个表格里面所在的单元格高亮。

当所有小组赛全部打完之后，在页面上生成一个可以开合的列表，提示信息写小组出线名单，下面放一个列表写所有出线的小组名单。

对于淘汰赛，按照经典的展示淘汰赛方法画一颗二叉树。该二叉树根节点位于正中央，往两边分出左右半区。每一个选手显示在一个方形小卡片里。同样，点击该卡片可以查看选手的详细信息，除非该选手是“未确定”或者“轮空”。二叉树的分叉大概长这样：

```
----|
    |
    |----
    |
----|
```

当然，这是一个抽象的画法，我只是想表达你都需要用直角。每一个分叉也都可以点，点开之后会显示这一把的详细信息，前面还已经说过了。

整棵树上的数据需要通过已知信息计算得到。如果还没有抽签，那么叶子节点上也全部都是“未决定”。如果抽了签，则在叶子上填上对应的选手。如果一个场次结束了，就在那个分叉中，右边中间那条横线的上下面分别显示对应选手的大比分，然后计算出父亲节点的信息（胜者）。如果儿子里面有一个是“轮空”，那么父亲直接设置成另一个。

## 后台

后台是一个可以运行在 localhost:4000 上的 http server。这个你可以假设只在 PC 端运行。后台的前端样式和上面的前端几乎一样，主要区别如下：

首页所有赛事上方有一个按钮上面写“+添加赛事”。点击该按钮之后，弹出一个卡片（关闭方式和背景变暗，后面我不再赘述这种弹出卡片的样式了，在后台关闭卡片不会发生任何事，只有确认才会发生数据修改），我可以在上面输入比赛名称、比赛时间、比赛地点，然后点取消或者确认。如果我点了确认，在数据库生成相应的条目。

每一个赛事除了有一个可以点进去的按钮之外，还有两个按钮，一个是编辑，一个是删除，按钮样式都是对应的 icon。点编辑会弹出和上面一样的卡片，确认之后相应更新数据库。点击删除之后先弹出警告，确认之后才确实删除该赛事的整个文件夹。

每个赛事页面，所有项目上面有一个“+添加项目”。点击该按钮之后弹出一个卡片，需要输入以下信息：

1. 选择项目性质，这里给两个复选框，分别选择（男子 / 女子 / 混合）和（单打 / 双打 / 团体）。
2. 选择赛程，给一个复选框选择 小组赛-淘汰赛，淘汰赛，循环赛。
3. 上传选手名单。这里要求上传一个 csv，对格式有如下要求：
    1. 如果是单打，包含三列，依次为选手姓名，队伍，种子级别。
    2. 如果是双打，包含四列，依次为选手 1，选手 2，队伍，种子级别。
    3. 如果是团体，包含至少 3 列，依次为队伍，种子级别，后面是选手列表，选手至少有一个。
4. 如果选择了小组-淘汰赛，再给一个输入框。我可以在里面输入形如 ``x1*y1(z1) + x2*y2(z2) + ...`` 的表达式，表示我有 x1 个 y1 人组，每组出线 z1 个人；x2 个 y2 人组，每组出线 z2 个人，......。
5. 如果选择了小组-淘汰赛或者淘汰赛，在给一个输入框输入淘汰赛轮数 $d$。

点击确定后，如果信息对的上：

1. 淘汰赛人数（即小组赛出线人数总和）位于 $(2^d - 1, 2^d]$。
2. 小组赛选手数等于选手名单中的选手数。
3. csv 格式。

就修改数据库。如果不对，弹出错误信息让人修改上面的东西。每一个项目一创建，其元数据就不允许修改，但是可以整个删掉，在进入按钮旁边再给一个删除按钮。依旧是点击删除之后先弹出确认窗口。

小组赛刚创建时，每个小组里面的选手列表都是“未确定”。小组赛页面上面有一个按钮（抽签，如果已经抽签，就写重新抽签），点击之后根据*小组赛抽签逻辑*抽签。

淘汰赛页面一开始也是所有选手都是“未确定”，也给一个按钮（抽签，如果已经抽签，就写重新抽签），根据*淘汰赛抽签逻辑*抽签。如果人数不够，补充种子级别为 $-1$ 的“轮空”。

对于每一个点开场次之后弹出的面板，在列表下面给一个 + 按钮，点了之后可以输入一个比分。每个比分条目也都可以修改或者删除。

以上提到的所有*逻辑*，都独立写成文件并提供接口。现在先将所有的抽签逻辑写成纯随机抽取，不管种子级别；排名逻辑直接按照胜场排，如果并列随便排。我们后面来细化这部分实现。
