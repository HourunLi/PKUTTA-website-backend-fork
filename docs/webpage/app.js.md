# `webpage/app.js`

The shared client application uses hash routes so every public page works from one static `index.html`, including GitHub Pages subpaths. In public mode it reads the normalized live database directly: `./database/index.json` lists competition slugs, each competition's `meta.json` lists event slugs, each event's `meta.json` lists stages, and each stage provides `metadata.json` and `data.json`. Parallel metadata reads assemble the same in-memory shape as the admin API. Network reads use `cache: 'no-store'`; a 60-second in-memory cache stores both raw public JSON and aggregate route data. Concurrent readers share one request. Cloned aggregate results isolate dialog edits from cached snapshots. In admin mode it calls the equivalent local `/api/competitions` endpoints, and sends mutations for competitions, events, draws, games, match metadata, and group schedules.

Navigation immediately renders cached content and preserves the shell, breadcrumbs and known titles during first loads. Public metadata, cards and stages appear as separate requests complete; progress subscriptions also serve routes attaching to an already-running read. Switching stages of the same event reuses the current event immediately and performs no additional requests while the event cache is fresh. After 60 seconds, entering a cached route refreshes it while keeping its existing content visible; a browser reload starts an empty cache. Navigation serials prevent older responses from replacing later routes. Successful mutations invalidate the affected competition's raw and aggregate data plus the home listing, and a generation counter discards every older in-flight read and reuses or starts a fresh request, preventing stale scores from repopulating the cache. A refresh caused by a score save also checks its route and modal identities before rendering or reopening a match. Partially loaded content survives a failed remaining block with an inline error.

The header uses `icon.jpg` as the association logo (`/icon.jpg` in admin and `./icon.jpg` in public), and exposes a search icon instead of the former right-side home link. Search is disabled without a current competition. The 搜索比赛场次 dialog accepts a trimmed, case-insensitive member-name substring and searches every event and stage in the current competition, including group participant indexes, round-robin indexes, direct knockout participants and the bronze match. Singles, pairs and teams use the shared participant-name formatter. Results are one-column table rows showing project/stage, players, completion and WO-aware score, planned time/table and actual referee; unfinished rows are highlighted. A 正在搜索 status card remains visible while each project loads, ready projects append results in event order, and a failed project has its own visible error without discarding other results. Search requests reuse the data cache. Identity and per-dialog search serial checks prevent old searches from replacing newer results or reopening closed dialogs. Search forms work in both public and admin modes and preserve the existing button-only close and focus trap.

Creating a competition includes an always-visible filename input that is initially disabled and optional. Checking 自定义文件名 enables and requires it. Only a checked creation form sends a trimmed `slug`; ordinary creation leaves slug generation to the server. Existing competition editing does not expose a rename field. Help text describes the backend's lowercase-letter, digit and hyphen slug format.

The app renders competition and event cards, stage tabs, group and round-robin tables, and a horizontally scrollable knockout tree whose branches use right-angle SVG connectors. Its local `rankRoundRobin()` calculation is used only for standalone round-robin: match wins, won games, and all points scored in completed games, then the same three measures among exactly tied players, then display name. WO contributes zero to game/point metrics, while one-sided forfeits award a match win to the opponent. Incomplete games contribute no games or points. Group ranking and qualifiers use the server's persisted `group.standings`, so a ranking decided by a draw stays identical in public and admin views and after refresh. The participant and match dialogs are shared between public and admin views. Admin dialogs expose CSV event creation, draw and redraw, direct per-game score inputs, and match table/time/referee/completion controls. The CSV helper text explains that seed level 0 is valid and larger values have higher priority. Server-side validation remains authoritative.

Both round-robin and group tables render score cells above and below the diagonal, with 56px column widths to fit `wo:wo`. The three group tables share the standings table's original 43px header and 46px content row heights. Layout markup includes `two-table-layout` whenever no standings are visible, centering the fixed-width roster and matrix together on desktop; a visible standings table fills the remaining width. Symmetric cells use the same match ID and invert the displayed A:B score according to the row participant; both open the same match dialog. Finished matches apply their highlight to the entire table cell. Existing score-save refreshes rerender both cells from their shared match record. Standalone round-robin keeps toggleable roster ranking columns. Group rosters contain only # and 选手. Each completed group adds a third ranking table with 名次, 选手 and 积分, plus 同分内部积分, 局胜负比, 球分胜负比 or 抽签名次 only when used by any row. Ratio traces display won:lost, preserving zero denominators without rounding. Unused metric cells are blank and gray; qualifier names are highlighted in both roster and standings. Once all groups finish, a collapsible qualifier table with 小组, 选手, and 出线名次 appears before the group cards. Its order and ranks also come from server standings.

Every group header displays `scheduled_time`, `scheduled_table` and `scheduled_referee`, using 待定 for unassigned fields. Admins can open a group schedule dialog and PATCH `/api/competitions/<competition>/events/<event>/groups/<group-id>` with all three fields. Empty strings clear the corresponding schedule. The dialog explains that saving overwrites time, table and referee for every match in that group, while later changes to an individual match do not change the group's schedule. A successful save refreshes the group stage. Match details display the actual referee and allow an independent `referee` edit.

The knockout tree numbers every leaf #1 through #N, including byes and undecided slots. One-sided WO advances the opponent; a completed double WO advances a bye, matching the server. The independent bronze match appears below the championship final. Its score opens the shared match dialog and uses the ordinary knockout match API with match ID `bronze`. Once the server includes `stage.data.results`, a collapsible 比赛结果 table appears before the bracket in server-provided order, with the participant column titled 选手 for every event format. Missing bronze and results fields in older stage JSON leave the existing bracket usable.

The admin match dialog lists every game as two independently editable text inputs accepting integers 0–99, case-insensitive WO, or blank, and a direct delete button. WO is normalized to `wo`; when its opponent is blank, that side is normalized to 0, so entering one WO awards one game to the opponent. Match scores mark any forfeiting side as `wo`; double forfeits display `wo:wo` and may be finished. Adding a game immediately persists `[null, null]`; clearing an ordinary score sends `null`. A game with either ordinary score unfilled stays visible in the admin dialog but does not contribute to the match score or live-score indicator. A changed input saves the row's two current values automatically; saves for the same row run serially so rapid edits cannot be overwritten by out-of-order responses. The dialog stays mounted while saving, preserving focus, and synchronizes its completion label and checkbox after successful score edits. Adding, deleting, finishing, or closing a match waits for outstanding score saves before refreshing the event. Saving match information removes unfilled games on the server, then refreshes the admin list. Public match details omit all games with either score missing and show an empty-list message if no complete games remain.

The admin-only floating Submit button POSTs `/api/submit` and polls the matching GET endpoint until its `running` flag clears. A single serial protects against stale initial reads and repeated clicks; one poll runs at a time. Busy state survives page rerenders and reloads, disables the button and renders it gray. A lost POST response is reconciled by reading server status; a failed poll retries without reenabling an unconfirmed running job. Success is silent; failure opens a warning dialog with escaped server error text. Initial idle state does not display old errors. Public mode exposes no Submit control. All dialogs close through their buttons; overlay clicks and Escape no longer close them. Keyboard Tab remains within the active dialog.

The footer contains the association name only. `updateEventFields()` toggles the group-specification and knockout-round controls when the event schedule changes; CSS must honor their `hidden` attributes.

CSV uploads are decoded from bytes with fatal UTF-8 validation, then fatal GB18030 decoding for Windows Excel/GBK exports. Uploads that cannot be decoded, or that already contain the Unicode replacement character, are rejected with a visible error before event creation.
